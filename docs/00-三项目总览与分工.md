# 澄读 · 三个优化项目：总览与分工

> 适用对象：主窗口（你）+ 三个并行 Agent（本地库 / 分享 / 对比）。
> 目标：三个功能可以同时开工，互不踩文件，合并时只冲突一次。

---

## 一、三个项目是什么

| 编号 | 项目 | 一句话 | 解决的病 |
| --- | --- | --- | --- |
| WP1 | 本地论文库 | 解析过的论文存在浏览器里，下次直接打开 | 没有复访理由 |
| WP2 | 分享链接 | 把一篇的解析结果生成只读链接 | 没有传播、没有缓存复用 |
| WP3 | 对比阅读（轻量版） | 两篇论文按同一套维度并排看 | 单篇工具做不了"比较" |

三个都属于"让一次使用留下东西"，方向一致，不冲突。

---

## 二、四条先定死的决策

1. **本地优先**：用户数据默认只存浏览器（IndexedDB）。服务端只存"用户主动点分享"的那一份。
2. **服务端不存原文**：分享只放解析结果（`AnalysisResult` JSON），不放论文全文。降低版权与存储责任。
3. **对比先做规则版**：差异由预置数据显式标注（`diff: same | different | conflict`），**不调模型**。等有人用再加 AI 归纳。
4. **本期不做账号**：不注册、不手机号、不微信。身份用匿名 `deviceId`（本地 UUID），为将来的"迁移码"留口子。

---

## 三、共享地基（必须先做，约 0.5 天，一个 Agent 单独完成）

三个功能都要动 `App.tsx` / `router.ts` / `contracts/`，所以先落一层"插座"，之后各干各的：

1. `contracts/library.ts`、`contracts/share.ts`、`contracts/compare.ts` —— 只放 schema 与类型，先写接口不写实现。
2. `api/router.ts` —— 挂两个空 router：`share`、`library`（后者留空，本期不用）。
3. `src/App.tsx` —— 只加三处：
   - 顶部导航多一个入口 `我的论文`（打开 LibraryPanel 的开关）
   - 工作台多一个 tab `compare`（内容先渲染 `<div>对比占位</div>`）
   - 一个 `view` 状态：`'home' | 'compare'`
4. `src/main.tsx` —— 引入三个新样式文件（见下）。
5. `src/styles/` —— 新建 `library.css`、`share.css`、`compare.css`，各自由对应 Agent 独占追加，**不要动 `app.css`**。

> 地基做完再并行，后面三个 Agent 对 `App.tsx` 的改动都能压到 5 行以内。

---

## 四、并行分工

| Agent | 独占文件 | 允许小改（≤10 行） | 依赖 |
| --- | --- | --- | --- |
| A · 本地库 | `src/lib/library.ts`、`src/components/LibraryPanel.tsx`、`src/styles/library.css` | `App.tsx`（注册入口）、`main.tsx`（引样式） | 地基 |
| B · 分享 | `api/shareRouter.ts`、`src/components/ShareDialog.tsx`、`src/styles/share.css` | `api/router.ts`、`contracts/share.ts`、`wrangler.jsonc`（KV 绑定） | 地基 |
| C · 对比 | `src/lib/sample2.ts`、`src/lib/compare.ts`、`src/components/CompareBoard.tsx`、`src/styles/compare.css` | `App.tsx`（注册 tab）、`main.tsx` | 地基；A 的本地库可选（先只对比两篇预置） |

**冲突热点与规则**

- `App.tsx`：三个人各改各的区块，谁都不许重排别人的 JSX。改完在 PR 描述里贴 diff 行号。
- `contracts/`：地基阶段一次性建好，之后只增字段不改名。
- `wrangler.jsonc`：只有 B 改（加 `SHARE` KV 命名空间）。
- `app.css`：**谁都不许动**。新样式进自己的 css。

---

## 五、建议的合入顺序

1. 地基（0.5d）
2. WP3 对比（3–3.5d）——它最依赖 `App.tsx` 的视图切换，先落地最省事
3. WP1 本地库（3d）与 WP2 分享（2d）并行
4. 合并后统一跑一次 `npm run check && npm test && npm run build`

---

## 六、验收口径（三个一起看）

- [ ] `npm run check`、`npm test`、`npm run build` 全绿
- [ ] 断网重开，本地库里的论文仍可看（证明真本地）
- [ ] 分享链接在无痕窗口能打开，删除后返回 404
- [ ] 对比页在 375px 宽不横向溢出
- [ ] 没有任何一篇论文全文被写进服务端（抽查 KV 与日志）
- [ ] 首屏包体没有因为新功能明显变大（OCR 资源仍是按需加载）

---

## 七、风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| IndexedDB 写入配额（Safari 7 天清理无访问站点数据） | 用户"存的论文没了" | UI 明示 + 导出/导入兜底 |
| KV 写次数（免费 1000 次/天） | 分享生成失败 | 只在点分享时写；失败给明确文案 |
| 三个 Agent 同时改 `App.tsx` | 合并冲突 | 地基 + 区块约定 |
| 分享页被搜索引擎收录，含用户论文解析 | 隐私 | 只读页加 `noindex`，并提示"公开可见" |

---

## 八、数据归属与账号（详见 `04-数据归属与合规.md`）

一句话结论：**你能看到，但别存正文；别做注册，用匿名 + 迁移码；用户协议不能当免责金牌。**
