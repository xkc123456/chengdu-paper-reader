# 数据归属、后台看板与账号：到底要不要做

> 回答三个问题：
> ① 用户保存后，我能不能在后台看到？
> ② 保存要不要注册（手机号/微信）？
> ③ 用户协议写"同意上传"够不够？

---

## 1. 先分清两种"保存"

| | 本地保存（WP1） | 云端保存（本期不做） |
| --- | --- | --- |
| 数据在哪 | 用户浏览器 IndexedDB | 你的 KV / D1 / R2 |
| 你看得到吗 | **看不到** | 看得到 |
| 成本 | 0 | 存储 + 带宽 + 备份 |
| 法律负担 | 几乎为 0 | 你成为"个人信息处理者 + 存储服务提供者" |
| 跨设备 | 不能 | 能 |
| 丢失风险 | 清缓存就没了 | 你负责不丢 |

**你问的"后台看到用户存的东西"，只有云端保存才成立。** 本期方案是本地保存，所以严格说：**你看不到，也不需要看到。**

---

## 2. 如果一定要"看到"，三种做法

### A. 本地 + 匿名聚合（推荐，本期就能做）

只上报**统计字段**，不上报内容：

```ts
{ event: "analyze" | "save" | "share",
  field: "经济学",           // 模型判定的学科
  wordCount: 8421,
  difficulty: "入门",
  minute: 8,
  at: "2026-11-01T..." }     // 不含标题、不含正文、不含院校
```

看板就一页 `/admin/stats`：今天多少篇、学科分布、平均字数、保存率、分享率。
- 成本：KV 每天 1000 写够用；或 D1 免费 5GB。
- 法律：不含个人信息，压力最小（仍建议在隐私政策里说明"匿名统计"）。
- 能回答的问题：**有没有人在用、用的是什么学科、卡在哪一步**——这才是你要的"看用户"。

### B. 云端保存 + 用户可见（中期）

用户点"备份到云端"，数据存你的库里，**用户能在页面里看到、删除、导出**。
- 需要：匿名账号（deviceId）+ 删除接口 + 隐私政策 + 数据导出。
- 技术：D1（SQLite）一张表 `papers(id, device_id, title, field, payload_json, created_at)`；R2 存大 JSON 更便宜。
- 法律：个人信息处理者义务全套（告知、同意、删除、泄露通知）。

### C. 全量云端 + 你能随便看（不推荐）

等于你替用户保管论文。一旦泄露，责任在你；用户上传的论文若侵权，你"知道"后有处理义务。
**除非做企业版签合同，否则别碰。**

---

## 3. 注册：手机号 / 微信，值不值

先看工程量：

| 方案 | 技术工程量 | 法律/运营工程量 | 体验收益 |
| --- | --- | --- | --- |
| 匿名 deviceId | 0.5d | 0 | 换设备就丢 |
| 匿名 + 迁移码（一串字符） | 1d | 0 | 覆盖 90% 换设备场景 |
| 手机号 | 2–4 周（短信服务商实名、模板报备、验证码防刷、找回、注销） | 隐私政策、个人信息清单、注销机制、短信合规 | 真实身份、可找回 |
| 微信登录 | 2–4 周（需企业主体、开放平台审核、UnionID 体系） | 同上 + 平台协议 | 转化最好 |

**结论：现在别做。** 理由：
1. 你的核心价值是"读论文"，不是"账号"；
2. 注册会把"第一次体验"从 30 秒拉长到 2 分钟，转化直接掉；
3. 一旦有账号，你就有了"注销权、数据可携权、泄露通知"等一整套法定义务，**这些不是写个协议就完事的**；
4. 等你日活到 500 左右，再上"迁移码 → 手机号"的渐进路径，成本最低。

**替代方案（1 天）**：本地生成 `deviceId`，设置页给一个"迁移码"（把 deviceId + 加密后的库导出成一串 Base58）。换设备输入即可恢复。体验接近账号，零合规负担。

## 4. 用户协议写"同意上传"够不够？

**不够。** 三个原因：

1. **同意不等于免责**。个人信息保护讲"最小必要 + 目的限定 + 可撤回"。你写了"同意上传"，但如果没有"删除"和"撤回"，仍然不合规。
2. **内容责任是另一回事**。用户上传侵权论文，平台在"知道"后要处理（通知—删除）。协议里写"用户保证有权使用"只是把责任转给用户，**对外你仍有义务**。
3. **"保证不作非法使用"是承诺，不是挡箭牌**。真出事时，监管看的是你有没有做分级、留存、审计，而不是你有没有写这句话。

**最低限度要有的三样**：
- 隐私政策（收集什么、为什么、存哪、存多久、怎么删）
- 用户协议（禁止上传无权使用的文献、禁止分享未公开数据）
- 一个真的能用的"删除我的数据"入口

## 5. 我的建议路线

| 阶段 | 做什么 | 成本 |
| --- | --- | --- |
| 现在（本周） | 本地库 + 分享 + 对比；服务端只存分享的解析结果 | 已拆成三个 WP |
| 下一步（有 100 个用户后） | 匿名统计看板（A 方案）+ 隐私政策 + 删除入口 | 2d |
| 再下一步（有 500 日活） | 迁移码 → 手机号登录 → 云备份（B 方案） | 2–3 周 |
| 规模化后 | 备案、等保、内容审核流程 | 另算 |

---

## 6. 今天就能定的五件事

1. 保存 = **本地**，不是云端（省掉 80% 的合规问题）
2. 看板 = **匿名聚合**，不存正文
3. 注册 = **不做**，用 deviceId + 迁移码
4. 分享 = 只存解析结果，可删除，`noindex`
5. 用户协议 = 要写，但**别指望它免责**；配套的删除入口比协议更重要
