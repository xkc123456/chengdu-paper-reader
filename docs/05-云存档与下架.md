# 云存档与一键下架（已实现）

> 对应代码：`contracts/archive.ts`、`api/archiveRouter.ts`、`api/lib/archives.ts`、`api/lib/adminArchive.ts`
> 后台入口：`/admin?key=<ADMIN_KEY>` → 「论文云存档」区块

---

## 1. 它做了什么

| 角色 | 动作 | 结果 |
| --- | --- | --- |
| 用户 | 点工作台的 **存到云端** | 解析结果（+ 可选原文）写入 KV，列表可见 |
| 用户 | 调 `archive.remove` | 真删，并留一条 `user deleted` 日志 |
| 站长 | `/admin` → 云存档列表 | 只看到元信息：时间 / 标题 / 学科 / 设备短码 / 大小 |
| 站长 | 点「查看」 | 单篇详情页：原文 + 解析 JSON |
| 站长 | 点「一键下架」+ 填原因 | **真删**（`a:` 与 `m:` 都删），写一条不含正文的下架日志 |

**关键设计**：列表只扫 `m:` 元信息，正文只在「查看」单篇时读一次；下架日志只记 `id / 标题 / 原因 / 时间`，不记正文。

---

## 2. 上线前要做的两件事

```bash
# 1) 建一个独立的 KV 命名空间，把返回的 id 填进 wrangler.jsonc 的 ARCHIVE
npx wrangler kv namespace create ARCHIVE

# 2) 设置后台口令（后台没有它就是 404）
npx wrangler secret put ADMIN_KEY

# 3) 部署
npm run build && npx wrangler deploy
```

预期：`/admin?key=...` 能看到「论文云存档（0 篇）」，点「存到云端」后变成 1 篇。

---

## 3. 数据结构

```
a:<paperId>           全文：{ paper, deviceId }           ← 仅「查看」时读
m:<paperId>           元信息：{ id,title,field,at,deviceId,size,hasSource }
t:<timestamp>:<id>    下架日志：{ at,id,title,reason }     ← 不含正文
```

上限：单篇 **400KB**（超出直接拒绝）；每人每小时 **30 次**。

---

## 4. 接口

| 方法 | 入参 | 返回 |
| --- | --- | --- |
| `archive.save` | `{ deviceId, paper }` | `{ ok, id, at }` / `reason: unavailable \| rate-limited \| too-large` |
| `archive.mine` | `{ deviceId }` | `{ ok, items: 元信息[] }` |
| `archive.remove` | `{ deviceId, id }` | `{ ok }` / `not-found` |
